# FE-12: ChangeWorkOrderStatus UI

상태: 차단됨 (보류(Deferred))  /  선행: FE-07, BE-10, CON-02  /  Gate: deferred

## 목적

확정된 상태 전이표에 따라 작업지시 상태 변경 Command UI를 구현한다.

## 범위

- CON-02의 `ChangeWorkOrderStatus` 계약과 BE-10 API를 소비하는 Command adapter와 capability `Production.WorkOrder.ChangeStatus` action
- `Idempotency-Key`(동작당 1개, 재시도 재사용), `expectedVersion`(상세의 `rowVersion` Base64 문자열을 그대로 사용)
- 전이 실패(422)와 동시성 충돌(409) 처리
- operation feedback과 관련 Query만 갱신

## 제외 범위

- 전이표의 프론트 임의 정의
- 등록·수정·삭제
- 상태값·전이를 프론트에 하드코딩하는 것(허용 전이는 서버 응답·계약에서만 얻음)

## 관련 API/계약

Contract: `ChangeWorkOrderStatus`(BE-06·BE-07 확정), docs/specs/frontend/2026-10-07-mes-platform-frontend-design.md §8.5

## 관련 화면/모듈

`modules/production/work-orders/api/workOrderCommands.ts`, `ui/WorkOrderCommandBar.tsx`

## 완료 조건

- [ ] BE-06이 확정한 전이만 UI에 노출된다
- [ ] 성공·422·409 시나리오가 각각 검증되고 requestId·operationId를 확인할 수 있다
- [ ] 같은 동작 재시도는 같은 Idempotency-Key를 쓰고 새 동작은 새 키를 쓴다
- [ ] 상태 변경 후 관련 Query만 갱신된다

## 테스트 방법

Vitest, Playwright(mock과 가능하면 실제 API)
