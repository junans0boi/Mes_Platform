# DB-01: Database 프로젝트, DDL 구조, 공통 schema, WorkOrder 테이블과 index

상태: 선행 완료 시 착수 가능  /  선행: BE-01, CON-01  /  Gate: integration

## 목적

`database/`의 소유권을 만들고 BE-07이 읽을 WorkOrder 기본 스키마를 제공한다.

## 범위

- `database/MesPlatform.Database` 프로젝트와 DDL 적용 방식(순서 있는 스크립트 또는 sqlproj 중 선택, 선택 근거를 `docs/decisions/`에 기록)
- 공통 규칙 적용: `dbo` schema, PascalCase, FK를 DDL의 일부로 관리
- 핵심 테이블: `Plant`, `WorkOrder`, `WorkOrderStatusHistory`와 이들이 의존하는 최소 기준 테이블, CON-01 WorkOrder 목록·상세 필드를 만족하는 컬럼, `RowVersion rowversion NOT NULL`, `Plant.PlantId int NOT NULL` PRIMARY KEY
- 목록 허용 sort·필터마다 대응하는 index: database design §4.2의 "WorkOrder 목록 index 대응표"(`plannedStartAt`, `workOrderNumber`+prefix, `status`, `priority`, `lineId`, `productModelId`)를 그대로 구현
- WorkOrder 컬럼의 NULL 허용·기본값은 계약(`contracts/openapi.yaml`)의 `required`/`nullable`과 일치시킨다: `GoodQuantity`·`DefectQuantity`는 NOT NULL 기본 0, `LineId`·`ProductModelId`·`Priority`·`PlannedStartAt`·`PlannedEndAt`·`ActualStartAt`·`ActualEndAt` 등 계약에서 nullable인 항목만 NULL 허용(계약의 nullable 키는 값이 null일 뿐 항상 존재한다)
- WorkOrder 컬럼 정의를 database design 문서에 추가
- 로컬·테스트 DB 적용 스크립트와 운영 DB 차단 검사

## 제외 범위

- `WorkOrder.Status` 값 CHECK·enum 제약(BE-06 확정 전까지 허용 값을 DB에 하드코딩하지 않음)
- ProcessUnitStatusCurrent, Queue, Sequence (DB-02)
- ProcessResult, EquipmentLog 등 대용량 테이블
- 대표 데이터 seed (BE-09)
- 운영 DB 적용

## 완료 조건

- [ ] 빈 로컬 DB에 스크립트가 처음부터 끝까지 적용되고 재실행해도 안전하다
- [ ] CON-01 WorkOrder 필드가 모두 컬럼 또는 조인으로 제공 가능하다
- [ ] database design §4.2의 WorkOrder index 대응표 7종이 모두 정의되어 있고, 각 sort·필터 조회가 해당 index를 사용한다(실행 계획 검증)
- [ ] `workOrderNumberPrefix` 조회는 `LIKE @prefix + '%'`만 사용하고 `%…%` 부분 일치는 구현하지 않는다
- [ ] FK가 DDL로 존재한다
- [ ] WorkOrder 컬럼의 NULL 허용·기본값이 계약의 `required`/`nullable`과 일치한다(`GoodQuantity`·`DefectQuantity` NOT NULL 기본 0)
- [ ] `dbo.WorkOrder.RowVersion`이 `rowversion NOT NULL`이고 갱신 시 값이 자동으로 바뀐다
- [ ] `dbo.Plant.PlantId`가 `int NOT NULL` PRIMARY KEY다(Plant 참조 컬럼은 같은 타입)
- [ ] `Status`에 허용 값 제약이 없다
- [ ] 운영 DB에 자동 적용되지 않는다
