# FE-11: 초기 성능 benchmark와 목표 수치 검토

상태: 선행 완료 시 착수 가능  /  선행: FE-07, FE-10, BE-09  /  Gate: performance

## 목적

목표 수치를 실제 환경과 대표 데이터로 처음 측정하고 조정 필요 여부를 정리한다.

## 범위

- 서버 응답시간(API p95)은 BE-09의 측정 결과를 사용하고, 브라우저 화면 반영시간을 별도 지표로 측정
- 지표: 목록·검색·상세 p95, process-unit-status p95, 이벤트→화면 p95, Command→화면(해당 시), row 수, 초기 Shell route gzip bundle
- SUIT Variable 글꼴은 JS bundle과 별도의 정적 자산으로 측정한다. 파일 크기, 실제 전송량, 로딩 시점을 기록하고, 승인된 상한이 아직 없으면 현재 값을 기준선과 후속 자산 예산 결정 대상으로 명시한다
- 측정 환경·데이터·절차를 문서화하고 결과를 `docs/decisions/`에 기록
- 목표(§13.1) 대비 조정 제안

## 제외 범위

- 100만 건 ProcessResult benchmark(BE-09 범위 밖의 후속)
- 최적화 구현

## 관련 API/계약

docs/specs/frontend/2026-10-07-mes-platform-frontend-design.md §13

## 관련 화면/모듈

`docs/decisions/`, `frontend/mes-web/e2e/perf/`

## 완료 조건

- [ ] 모든 지표가 측정되고 서버·브라우저 지표가 분리되어 기록된다
- [ ] 측정 환경과 데이터 크기가 기록된다
- [ ] 목표와 다른 항목마다 조정 제안과 근거가 있다
- [ ] 초기 Shell route bundle이 300KB gzip 이하인지 기록된다
- [ ] SUIT Variable 글꼴 자산의 크기·전송량·로딩 시점을 JS bundle과 분리해 기록한다. 승인된 자산 상한이 없으면 상한 미정과 기준선 값을 명시하고 후속 결정으로 남긴다
