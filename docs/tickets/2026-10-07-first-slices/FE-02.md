# FE-02: 공유 계약 기반 타입 API client(typed client), ApiError mapper, MSW

상태: 선행 완료 시 착수 가능  /  선행: FE-01, CON-01  /  Gate: foundation

## 목적

공유 계약(CON-01)을 소비하는 typed client, ApiError mapper, MSW mock 기반을 프론트에 만든다. 계약 파일은 이 티켓이 만들지 않는다.

## 범위

- CON-01의 `contracts/openapi.yaml`에서 `openapi-typescript` 타입 생성 스크립트와 `openapi-fetch` 기반 `platform/api/httpClient.ts`
- `ApiError` mapper: `code,args,errors,requestId,operationId`
- 요청마다 `requestId` 생성·전달, AbortSignal 지원
- `plantId`를 httpClient가 주입하지 않음을 테스트로 고정
- MSW handler를 `contracts/openapi.yaml`에서 만드는 방법 확립

## 제외 범위

- `contracts/openapi.yaml`과 `contracts/realtime-events.md` 작성·수정 (CON-01)
- WorkOrder·ProcessUnitStatus 화면 코드
- refresh·logout endpoint (CON-02, BE-05 확정 후)
- 백엔드 구현

## 관련 API/계약

`contracts/openapi.yaml` (CON-01 소비), docs/specs/backend/2026-10-07-mes-platform-backend-design.md §9.3·§9.4·§17.1

## 관련 화면/모듈

`frontend/mes-web/src/platform/api/`

## 완료 조건

- [ ] 생성된 타입이 typecheck를 통과하고 생성물은 수정되지 않는다(`generated/`)
- [ ] envelope·오류 응답이 `ApiError`로 변환되며 `args`, `errors[]`가 보존된다
- [ ] 401·403·404·409·422·네트워크 오류가 구분된 `ApiError` 종류로 변환된다
- [ ] mock이 계약 파일에서 생성되며 계약과 다른 응답을 handler에 손으로 추가하지 않는다
- [ ] 단위 테스트가 mapper와 요청 id 부여를 검증한다

## 테스트 방법

Vitest 단위 테스트, 타입 생성 후 `git diff` 안정성 확인
