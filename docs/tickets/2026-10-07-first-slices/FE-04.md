# FE-04: 인증: 로그인, 메모리 token, 401 처리, capability·Plant guard

상태: 완료(로컬 검증, 2026-10-07)  /  선행: FE-02, FE-03  /  Gate: foundation

## 목적

로그인과 권한·Plant 범위를 공통 계층으로 만든다. silent refresh는 포함하지 않는다.

## 범위

- 로그인 화면과 session 조회
- access token 메모리 보관(localStorage·sessionStorage 금지)
- 401 공통 처리: 로그인 이동, 원래 URL 복귀 주소 보존, 동시 401 처리
- capability guard(메뉴·route·action)와 403 화면
- 현재 Plant 선택 컨텍스트(`platform/plant`)와 AppShell 표시, `allowedPlantIds` 밖의 선택 불가
- adapter가 plantId를 요청 모델에 담는 헬퍼(명시 전달)

## 제외 범위

- silent refresh, refresh cookie 처리 (FE-13, BE-05 확정 후)
- 서버 권한 검증(백엔드)
- 로그아웃 서버 호출 계약

## 관련 API/계약

CON-01의 login·session 계약(임시(provisional))과 FE-02의 typed client, docs/specs/frontend/2026-10-07-mes-platform-frontend-design.md §6.3, §8.6, §15

## 관련 화면/모듈

`frontend/mes-web/src/platform/auth/`, `platform/authorization/`, `platform/plant/`, `modules/auth/`

## 완료 조건

- [x] 토큰이 JS 메모리에만 있고 storage에 쓰이지 않는다(테스트로 검증)
- [x] 401 시 로그인으로 이동하고 로그인 후 원래 URL로 돌아온다
- [x] capability 없는 메뉴는 숨겨지고 직접 URL 접근은 403 화면이다
- [x] Plant 선택은 `allowedPlantIds`로 제한된다
- [x] 새로고침 시 재로그인이 필요함을 README에 개발 중 한계로 기록한다

## 테스트 방법

Vitest(guard, 토큰 저장 검사), Playwright(login, 401, 403, plant 전환)

## 완료 증거

Playwright 결과, storage 검사 로그

## 완료 기록 (2026-10-07)

- **구성**: `platform/auth/`(`tokenStore` 메모리 token, `unauthorizedBus` 401 공통 처리, `AuthProvider`, `returnTo`), `platform/plant/`(`PlantProvider`, `usePlant`, `withPlantId`), `platform/api/apiClient.ts`(앱 전체 typed client), `modules/auth/LoginPage`, `app/router/RequireAuth`, TopBar의 `PlantPicker`·로그아웃. Provider 순서는 QueryClient → Auth → Plant → I18n → UI.
- **401 처리**: 로그인 요청 자체의 401(`INVALID_CREDENTIALS`)은 제외하고, 그 외 401은 세션을 끝내며 서버 상태 cache를 비운다. 동시에 여러 요청이 401을 받아도 한 번만 처리한다(다음 로그인 성공 시 재무장). 로그인 이동은 `RequireAuth`가 현재 주소를 `returnTo`로 보존해 수행하고, `returnTo`는 앱 내부 경로만 허용한다(open redirect 방지).
- **capability**: 기본값을 "모두 허용"에서 "모두 거부"로 바꿨고 `AuthProvider`가 세션 값을 채운다. 메뉴·route guard·403 화면은 FE-03 구현을 그대로 쓴다.
- **Plant**: 선택지는 세션의 `allowedPlantIds`뿐이다. 저장된 선택이 허용 범위 밖이면 무시한다. Plant 이름 API가 없어 `Plant {id}`로 표시한다.
- **기존 e2e 변경**: 새로고침하면 재로그인하므로 기존 spec은 `gotoAuthed`(로그인을 거쳐 원래 주소로 진입)를 쓰도록 바꿨다.
- **검증**: `npm run typecheck`, `lint`, `format:check` 통과. Vitest 10 파일 101 테스트 통과(신규 36: returnTo, withPlantId, 로그인·복귀·401·cache·storage 검사·capability·Plant). Playwright 14개 통과(신규 6: 로그인 복귀, 잘못된 암호, storage·cookie 검사 로그, 401 이동, 403 화면, Plant 전환). storage 검사 로그: `{"localKeys":[],"sessionKeys":[],"cookie":""}`.
- **환경 메모**: 이 샌드박스는 Playwright가 기대하는 Chromium 빌드가 없어 설치된 Chromium을 지정한 임시 설정(커밋 제외)으로 실행했다. CI는 `npx playwright install`을 쓴다.
- **남은 것**: silent refresh·서버 로그아웃(FE-13), 실제 서버와의 로그인 통합(FE-14, BE-03은 이미 구현).
