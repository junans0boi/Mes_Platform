# FE-06: WorkOrder 목록 (읽기 전용)

상태: 선행 완료 시 착수 가능  /  선행: FE-04, FE-05, CON-01  /  Gate: foundation

## 목적

작업지시 목록을 서버 cursor로 조회하고 검색·정렬을 URL에 반영한다.

## 범위

- CON-01의 `GET /api/v1/production/work-orders` 계약을 소비(필터, sort, cursor, `plantId` query parameter). 계약 변경이 필요하면 CON-01 변경이 먼저
- `modules/production/work-orders` 모듈: route, query adapter, 모델·mapper, 검색(WorkOrderSearch), WorkOrderGrid
- 작업지시번호 검색은 접두 일치(`workOrderNumberPrefix`)이며 부분 일치 검색 UI·요청은 만들지 않는다
- capability `Production.WorkOrder.Read`
- MSW mock 데이터와 handler

## 제외 범위

- 상세(FE-07)
- 상태 변경(FE-12)
- 등록·수정·삭제
- 100만 건 seed
- `contracts/openapi.yaml` 직접 수정

## 관련 API/계약

Contract: CON-01의 `GET /api/v1/production/work-orders`, docs/specs/frontend/2026-10-07-mes-platform-frontend-design.md §9.1, §19 Slice B1

## 관련 화면/모듈

`frontend/mes-web/src/modules/production/work-orders/`

## 완료 조건

- [ ] 검색·정렬·cursor 변경이 URL과 API 요청에 반영된다
- [ ] 한 번에 최대 200개 row만 전송된다
- [ ] `plantId`는 adapter가 요청 쿼리에 명시한다
- [ ] capability 없으면 메뉴와 route에서 접근 불가
- [ ] 빈·오류·재시도 상태가 있다
- [ ] `requestId`를 오류 화면과 개발자 도구에서 확인할 수 있다

## 테스트 방법

Vitest(adapter, mapper), Playwright(mock): 검색, 정렬, cursor 이동, URL 복원, 오류 재시도
