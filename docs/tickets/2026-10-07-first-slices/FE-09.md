# FE-09: 실시간 coordinator: SignalR, 변경 id 재조회, version 병합

상태: 선행 완료 시 착수 가능  /  선행: FE-08  /  Gate: foundation

## 목적

무효화 이벤트를 받아 변경 id만 일괄 재조회하고 더 새로운 projectionVersion일 때만 교체한다.

## 범위

- `platform/realtime` coordinator: HubConnection, Plant 구독, 해제
- `ProjectionChangedEvent{projection,plantId,changedIds,reset?,asOf}` 처리
- 250ms 모음 창 후 `?ids=` 일괄 재조회(100개 상한, 초과 분할)
- 교체 규칙: 재조회 행의 `projectionVersion`이 캐시보다 클 때만 교체
- `reset` 또는 범위 불명 시 query invalidate
- 모음 창·상한·fallback 주기는 설정값
- unmount 시 구독 해제, 숨겨진 탭에서 갱신 중지
- 테스트용 fake hub

## 제외 범위

- 연결 상태 표시·fallback(FE-10)
- 이벤트 version 비교(사용하지 않음)
- 다른 projection

## 관련 API/계약

`contracts/realtime-events.md`(CON-01), docs/specs/frontend/2026-10-07-mes-platform-frontend-design.md §12, docs/specs/backend/2026-10-07-mes-platform-backend-design.md §13.3

## 관련 화면/모듈

`frontend/mes-web/src/platform/realtime/`, `modules/monitoring/process-unit-status/`

## 완료 조건

- [ ] 전체 목록을 주기적으로 재조회하지 않는다
- [ ] 오래된 `projectionVersion`의 재조회 결과가 최신 row를 덮어쓰지 않는다(단위 테스트)
- [ ] 순서가 뒤섞인 이벤트와 중복 이벤트(at-least-once 전달로 같은 이벤트가 다시 올 수 있음)를 안전하게 처리한다
- [ ] `reset=true`이면 `changedIds`를 사용하지 않고 해당 Query를 invalidate한다
- [ ] changedIds가 100개를 넘으면 분할 요청한다
- [ ] 250ms 안의 여러 이벤트가 한 번의 재조회로 합쳐진다
- [ ] unmount 후 구독과 timer가 남지 않는다
