# BE-12: 결정: Projection 변경 알림 전달 방식(transport)

상태: 선행 완료 시 착수 가능  /  선행: 없음  /  Gate: decision

## 목적

Worker와 Server는 별도 프로세스이고 SignalR Hub는 Server에 있다. Projection 갱신 후 변경 알림을 Hub까지 전달하는 경로를 결정하고 기록한다.

비게이팅 결정 티켓이지만 **DB-02와 BE-08의 필수 선행 조건**이다. 이 결정이 닫히기 전에는 DB-02(Outbox 스키마)와 BE-08을 시작하지 않는다.

권장 결정은 SQL Server Transactional Outbox다.

## 범위

- 전달 방식 확정: Worker는 Server Hub를 직접 호출하지 않고, Projection 행 Upsert·`ProjectionVersion` 기록·Outbox 기록을 **같은 transaction**에서 수행한다. Server의 Dispatcher가 Outbox를 claim해 SignalR Hub로 발행한다
- 전달 보장: at-least-once. 중복 발행을 허용하며 클라이언트는 `projectionVersion` 비교로 안전하게 병합한다(이벤트에 version 없음). 이벤트 간 순서는 보장하지 않는다
- Outbox 행 계약: `PlantId`, `Projection`, `changedIds` 또는 `reset`, `asOf`, 상태, attempt count, lease, `PublishedAt`, `LastError`
- Claim 방식과 lease: 여러 Dispatcher(다중 Server 인스턴스)가 같은 행을 동시에 발행하지 않도록 하는 claim 규칙, lease 기간
- Dispatcher 재시작: lease 만료 후 재claim, 발행 후 `PublishedAt` 기록 전에 중단되면 중복 발행될 수 있음을 명시
- 실패와 retry 정책: 다음 시도 시각(backoff), 최대 시도 횟수, 초과 시 `Failed` 상태와 운영자 확인 방법, `LastError` 기록
- Server 중단 시 유실 없음: Server가 내려가 있어도 Outbox 행이 남고 복구 후 발행됨
- 보관 정책: 발행 완료 행의 삭제·보관 기간
- 한 번에 `changedIds`가 상한을 넘을 때 `reset` 행으로 대체하는 규칙(`contracts/realtime-events.md`와 일치)
- Dispatcher의 실행 위치(Server의 hosted service)와 활성화 설정, 운영 설정값 목록(claim 크기, lease, backoff, 최대 시도, 보관 기간)
- 결정 결과를 backend design §13.4·§24.3과 database design에 기록하고 DB-02·BE-08이 소비할 입력 목록을 만든다

## 제외 범위

- SignalR backplane(다중 Server 간 Hub 전달): 다중 Server 확장 시 후속 범위
- Outbox 테이블 DDL 작성(DB-02), Writer·Dispatcher 구현(BE-08)
- Projection 계산 로직

## 완료 조건

- [x] 전달 방식(Transactional Outbox)과 at-least-once 정의가 backend design §13.4에 기록된다
- [x] Outbox 행 계약, claim·lease·retry·보관 정책의 값(또는 설정 이름과 기본값)이 기록된다
- [x] Dispatcher 재시작, 중복 발행, 발행 실패, lease 만료 시나리오별 기대 동작이 기록된다
- [x] Server 중단 중에도 이벤트가 유실되지 않는 근거(같은 transaction)가 기록된다
- [x] SignalR backplane이 후속 범위임이 기록된다
- [x] DB-02와 BE-08이 이 기록만 보고 착수할 수 있다
