# FE-05: 공통 데이터 패턴: ServerDataGrid cursor adapter, SearchPanel, URL 상태

상태: 선행 완료 시 착수 가능  /  선행: FE-02, FE-03  /  Gate: foundation

## 목적

목록 화면이 공통으로 쓰는 cursor 그리드, 검색 패널, URL 상태 직렬화, 공통 피드백을 만든다.

## 범위

- `ServerDataGrid`: MUI X DataGrid Premium 위의 cursor adapter(이전/다음, rowCount·페이지 번호 없음, cursor stack, 새로고침 시 첫 페이지 대체), 서버 sort, 가상화, 안정 row id, 선택·키보드 focus
- 정렬 변경 시 cursor 초기화, `CURSOR_SORT_MISMATCH` 시 첫 페이지 재조회
- column preference는 localStorage
- 타입 있는 `SearchField` union과 URL serializer(검색 조건·sort·현재 cursor·선택 id)
- PageFrame, PageHeader, SearchPanel, DetailDrawer, EmptyState, OperationFeedback(loading/empty/error/retry)
- page size 기본 50, 상한 200

## 제외 범위

- 업무별 컬럼·검색 정의 (FE-06, FE-08)
- 서버 grid preference 저장
- export
- 실시간 row patch (FE-09)

## 관련 API/계약

docs/specs/frontend/2026-10-07-mes-platform-frontend-design.md §9, §10, §11, docs/specs/backend/2026-10-07-mes-platform-backend-design.md §9.4

## 관련 화면/모듈

`frontend/mes-web/src/shared/ui/`, `shared/forms/`, `shared/lib/`

## 완료 조건

- [ ] 정렬 변경 시 cursor가 초기화된다(단위+E2E)
- [ ] URL을 복사해 열면 같은 조건·정렬이 복원된다
- [ ] 한 번에 200개를 초과해 요청하지 않는다
- [ ] loading·empty·error·retry 상태가 모두 구현되고 접근 가능한 텍스트를 가진다
- [ ] 새 검색 요청이 이전 요청을 취소한다
- [ ] 그리드는 업무 규칙, Snackbar 문구, 저장 프로시저를 알지 못한다

## 테스트 방법

Vitest(serializer, cursor stack), Playwright(예제 mock 목록)

## 완료 증거

테스트 출력, 예제 화면 캡처
