# FE-05: 공통 데이터 패턴: ServerDataGrid cursor adapter, SearchPanel, URL 상태

상태: 완료(로컬 검증, 2026-10-07)  /  선행: FE-02, FE-03  /  Gate: foundation

## 목적

목록 화면이 공통으로 쓰는 cursor 그리드, 검색 패널, URL 상태 직렬화, 공통 피드백을 만든다.

## 범위

- `ServerDataGrid`: MUI X DataGrid Premium 위의 cursor adapter(이전/다음, rowCount·페이지 번호 없음, cursor stack, 새로고침 시 첫 페이지 대체), 서버 sort, 가상화, 안정 row id, 선택·키보드 focus
- 정렬 변경 시 cursor 초기화, `CURSOR_SORT_MISMATCH` 시 첫 페이지 재조회
- column preference는 localStorage
- 타입 있는 `SearchField` union과 URL serializer(검색 조건·sort·현재 cursor·선택 id)
- PageFrame, PageHeader, SearchPanel, DetailDrawer, EmptyState, OperationFeedback(loading/empty/error/retry)
- page size 기본 50, 상한 200

## 제외 범위

- 업무별 컬럼·검색 정의 (FE-06, FE-08)
- 서버 grid preference 저장
- export
- 실시간 row patch (FE-09)

## 관련 API/계약

docs/specs/frontend/2026-10-07-mes-platform-frontend-design.md §9, §10, §11, docs/specs/backend/2026-10-07-mes-platform-backend-design.md §9.4

## 관련 화면/모듈

`frontend/mes-web/src/shared/ui/`, `shared/forms/`, `shared/lib/`

## 완료 조건

- [x] 정렬 변경 시 cursor가 초기화된다(단위+E2E)
- [x] URL을 복사해 열면 같은 조건·정렬이 복원된다
- [x] 한 번에 200개를 초과해 요청하지 않는다
- [x] loading·empty·error·retry 상태가 모두 구현되고 접근 가능한 텍스트를 가진다
- [x] 새 검색 요청이 이전 요청을 취소한다
- [x] 그리드는 업무 규칙, Snackbar 문구, 저장 프로시저를 알지 못한다

## 테스트 방법

Vitest(serializer, cursor stack), Playwright(예제 mock 목록)

## 완료 증거

테스트 출력, 예제 화면 캡처

## 완료 기록 (2026-10-07)

- **구성**: `shared/lib/`(`cursorPaging` cursor stack·page size 상한, `listUrlState` URL 직렬화, `useListUrlState`, `useCursorList` 취소·placeholder·`CURSOR_SORT_MISMATCH` 처리, `columnPreference`), `shared/forms/`(`SearchField` union, `SearchPanel`), `shared/ui/`(`ServerDataGrid`, `OperationFeedback`, `DetailDrawer`). 그리드는 업무 규칙·Snackbar 문구·프로시저를 모르고 열·행동을 주입받는다. 예제는 `modules/dev/GridExamplePage`(`/dev/grid`, 계약된 `listWorkOrders` 사용, FE-06에서 제거).
- **의존성**: `@mui/x-data-grid-premium@^8`(설계 §4.2). 그리드는 route chunk로 분리되어 초기 Shell JS gzip은 202.0 KB(예산 300 KB), 전체 704.6 KB.
- **설계 결정**: 이전 이동은 지나온 cursor stack, 새로고침으로 잃으면 첫 페이지로 대체. 정렬·조건 변경은 cursor와 선택을 지운다. 새 조건을 조회하는 동안 이전 페이지를 유지하되 이동 버튼은 `settledPage`(placeholder 제외)만 근거로 삼는다. URL 쓰기는 렌더된 상태가 아니라 가장 최근에 쓴 상태 위에 합성한다. 선택 id는 문자열이라 행 id 타입으로 되돌려 DataGrid에 넘긴다(숫자 id에서 선택이 안 보이던 문제를 테스트로 잡았다).
- **발견한 사실**: 주소가 바뀐 뒤 렌더가 따라잡기 전의 조작이 오래된 상태로 URL을 덮어쓰는 경쟁이 e2e에서 드러나 위 방식으로 고쳤다. 남는 경우(오래된 cursor)는 서버의 `CURSOR_SORT_MISMATCH`와 첫 페이지 재조회가 받는다.
- **검증**: `typecheck`, `lint`, `format:check`, `api:check`, `build` 통과. Vitest 19 파일 160 테스트 통과(신규 59: cursor stack, URL 직렬화 왕복·검증, hook 취소/placeholder/mismatch/limit 상한, SearchPanel, 그리드 상태·정렬·선택·열 설정, OperationFeedback). Playwright 25개 통과(신규 10: 50건 첫 페이지·다음/이전, 정렬 시 cursor 초기화, URL 복원, limit 200 상한, 가상화, 오류·재시도, 빈 상태, cursor 불일치, 요청 취소, 열 설정).
- **증거**: 예제 화면 캡처 `docs/evidence/FE-05/grid-example-1366x768.png`(라이선스 키가 없어 평가판 표시가 보인다).
- **환경 메모**: 이 샌드박스는 설치된 Chromium을 지정한 임시 설정(커밋 제외)으로 e2e를 실행했다.
- **남은 것**: 업무별 열·검색 정의(FE-06, FE-08), export·서버 grid preference(범위 밖).
