# FE-03: Provider, route registry, AppShell, i18n, UI context 구성

상태: 선행 완료 시 착수 가능  /  선행: FE-01  /  Gate: foundation

## 목적

Shell과 라우팅 골격을 만들어 모든 모듈이 같은 방식으로 등록되게 한다.

## 범위

- Provider 구성(QueryClient → Auth shell → I18n → Theme → RouterProvider)
- `createBrowserRouter` + route `lazy`, `routeRegistry.ts`와 `RouteMetadata`(path,titleKey,capability,module,icon,preserveState)
- AppShell(Header, Navigation, 워크스페이스 탭=URL 파생)와 BootState(영역별 로딩, 재시도)
- 메뉴를 registry에서 파생, capability 필터 훅 인터페이스
- i18n: ko/en/vi 구조, `common`·`shell` 번들, 모듈 namespace lazy, ko fallback과 개발 경고
- React Context + localStorage UI 설정(밀도·사이드바·알림 drawer), 토큰 저장 금지
- 디자인 토큰(설계 §14)과 ThemeProvider
- 임시 route 2개로 lazy 분리 검증

## 제외 범위

- 실제 인증 연동(FE-04)
- 업무 화면
- Zustand 도입
- KeepAlive

docs/specs/frontend/2026-10-07-mes-platform-frontend-design.md §5, §6, §14, §16

## 완료 조건

- [ ] 임시 route가 Shell 안에서 별도 chunk로 lazy loading된다
- [ ] 부트스트랩 실패 시 Shell 골격 위에 재시도 상태가 표시된다
- [ ] 메뉴와 route guard가 같은 metadata에서 나온다
- [ ] ko/en/vi 전환이 동작하고 누락 키는 ko로 대체되며 개발 중 경고한다
- [ ] localStorage에는 UI 설정만 저장된다(토큰 없음)
- [ ] 1366×768에서 Shell이 스크롤 없이 시작된다
