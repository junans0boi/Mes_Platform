# BE-11: 인증 refresh 구현

상태: 차단됨 (보류(Deferred))  /  선행: BE-05, BE-03, CON-02  /  Gate: deferred

## 목적

BE-05가 확정한 인증 계약에 따라 refresh token 발급·회전·재사용 감지를 구현한다.

## 범위

- refresh token을 HttpOnly + Secure + SameSite cookie로 발급(속성 값은 BE-05 결정)
- refresh endpoint, rotation, 재사용 감지 시 BE-05가 정한 동작
- logout 시 refresh 폐기
- CON-02 계약 준수

## 제외 범위

- BE-05가 정하지 않은 값의 추측
- 프론트 silent refresh(FE-13)

## 관련 API/계약

refresh·logout (CON-02; login·session은 CON-01 임시(provisional)), docs/specs/backend/2026-10-07-mes-platform-backend-design.md §15.3, §24.1

## 관련 화면/모듈

`src/*` Authentication feature, `database/`(저장소가 필요한 경우)

## 완료 조건

- [ ] cookie 속성이 BE-05 결정과 일치한다
- [ ] refresh마다 새 token이 발급되고 이전 token은 거부된다
- [ ] 재사용 감지 시 BE-05가 정한 처리를 한다
- [ ] 만료·폐기 token은 401이다
- [ ] 토큰·cookie 값이 로그에 남지 않는다

## 테스트 방법

API 통합 테스트

BE-05, CON-02 확정 및 BE-03 완료. 보류.
