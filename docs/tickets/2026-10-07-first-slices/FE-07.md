# FE-07: WorkOrder 상세 (master-detail)

상태: 선행 완료 시 착수 가능  /  선행: FE-06  /  Gate: foundation

## 목적

행 선택 시 상세만 조회하는 master-detail을 만든다.

## 범위

- CON-01의 `GET /api/v1/production/work-orders/{workOrderId}` 계약을 소비(`rowVersion` 포함)
- DetailPanel/Drawer, 선택 id를 URL에 반영, 선택 시 lazy query
- `rowVersion`(Base64 문자열)을 해석하지 않고 불투명 값으로 모델에 보존(후속 Command용)

## 제외 범위

- 상태 변경 UI·Command(FE-12)
- 수정 폼
- 관련 공정 실적 목록

## 관련 API/계약

Contract: `GET …/work-orders/{workOrderId}`, docs/specs/frontend/2026-10-07-mes-platform-frontend-design.md §9.2

## 관련 화면/모듈

`modules/production/work-orders/ui/WorkOrderDetailPanel.tsx`, api, model

## 완료 조건

- [ ] 행 선택 전에는 detail 요청이 없고 선택 시에만 요청한다
- [ ] 선택 id가 URL에 반영되어 새로고침 후 복원된다
- [ ] 404와 오류가 패널 안에 표시되고 목록은 유지된다
- [ ] `rowVersion`이 모델에 있고 UI에는 상태 변경 control이 없다

## 테스트 방법

Vitest, Playwright(mock): 선택, 복원, 404, 네트워크 로그로 요청 수 확인
