# BE-10: WorkOrder ChangeWorkOrderStatus API

상태: 차단됨 (보류(Deferred))  /  선행: BE-06, BE-03, BE-04, BE-07, CON-02  /  Gate: deferred

## 목적

BE-06이 확정한 상태 전이표에 따라 작업지시 상태 변경 Command API를 제공한다.

## 범위

- `ChangeWorkOrderStatus` Command Handler와 endpoint(CON-02 계약 준수)
- BE-06의 전이표를 Domain 규칙으로 구현하고 plan Task 2의 임시(provisional) 규칙을 교체
- `Production.WorkOrder.ChangeStatus` 권한, `plantId`를 `allowedPlantIds`와 대조
- `expectedVersion`(WorkOrder `RowVersion`의 Base64 문자열)을 디코딩해 `WHERE RowVersion = @Expected`로 낙관적 동시성 검사 → 불일치 시 409, 전이 위반 → 422, `Idempotency-Key`
- `WorkOrderStatusHistory` 기록과 OperationId·AuditLog 연결

## 제외 범위

- 등록·수정·삭제
- BE-06이 정하지 않은 전이
- 프론트 UI(FE-12)

## 관련 API/계약

`ChangeWorkOrderStatus` (CON-02), docs/specs/backend/2026-10-07-mes-platform-backend-design.md §17.2, §24.2

## 관련 화면/모듈

`src/*` Production/WorkOrders feature, `database/`

## 완료 조건

- [ ] BE-06 전이표의 모든 허용·거절 전이가 Domain 테스트로 검증된다
- [ ] 409·422가 CON-02의 `code/args`로 반환된다
- [ ] 오래된 `expectedVersion`은 409이고, 잘못된 Base64 형식은 400이다
- [ ] 성공 후 응답 또는 재조회의 `rowVersion`이 이전과 다르다
- [ ] 같은 `Idempotency-Key` 재요청이 한 번만 반영된다
- [ ] 다른 Plant 요청은 403이다
- [ ] 상태 이력과 Operation이 연결된다
- [ ] plan Task 2의 임시 규칙이 남아있지 않다
