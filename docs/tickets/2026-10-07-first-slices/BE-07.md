# BE-07: WorkOrder 조회 API (목록, 상세)

상태: 선행 완료 시 착수 가능  /  선행: CON-01, DB-01, BE-02, BE-03  /  Gate: integration

## 목적

WorkOrder 목록·상세 조회 API와 필요한 DB 스키마를 만든다. Command는 BE-06 확정 후 별도 작업이다.

## 범위

- CON-01의 `GET /api/v1/production/work-orders`(cursor, 허용 sort, 필터, `plantId`)와 `GET …/{workOrderId}`(`rowVersion` = SQL `rowversion`의 Base64 문자열) 구현. 계약과 다른 응답 금지
- DB-01 스키마를 읽는 Query(화면별 DTO, 필요한 컬럼만)
- `Production.WorkOrder.Read` 권한, `plantId`를 `allowedPlantIds`와 대조(BE-03)

## 제외 범위

- 상태 변경 Command(BE-10)
- 등록·수정·삭제
- WorkOrderProcess 상세
- DDL 작성(DB-01)
- p95 측정과 대표 데이터 seed(BE-09)

## 관련 API/계약

`contracts/openapi.yaml`(CON-01), docs/specs/backend/2026-10-07-mes-platform-backend-design.md §9, docs/specs/database/2026-10-07-mes-platform-database-design.md

## 완료 조건

- [ ] 응답이 CON-01 계약(envelope, cursor, 오류)과 일치한다
- [ ] `limit` 상한 200이 강제된다
- [ ] 상세의 `rowVersion`이 `WorkOrder.RowVersion`의 Base64 직렬화이고 같은 행을 다시 조회하면 변경이 없을 때 같은 값이다
- [ ] 정렬 키가 허용 목록으로 제한되고 정렬 변경 시 이전 cursor가 `CURSOR_SORT_MISMATCH`로 거부된다
- [ ] 다른 Plant 요청이 403이다
- [ ] 목록 Query가 DB-01의 index를 사용한다(실행 계획 또는 index 사용 검증 테스트)
- [ ] 통합 테스트가 동작한다(Application·Infrastructure·API)
