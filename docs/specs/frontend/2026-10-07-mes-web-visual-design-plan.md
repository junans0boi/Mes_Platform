`frontend-design` skill의 절차(계획 → 브리프 대조 검토 → 구현 → 캡처 비평)를 따른다. 이 문서에는 개정 이유, 개정 1과의 차이, 새 계획, 재작성한 자체 검토, 구현 후 비평을 남긴다.

## 0. 개정 이유

FE-03 개정 1을 구현해 화면을 캡처해 보니 기능은 통과했지만 시각적으로 촌스럽고 템플릿형 관리자 화면처럼 보였다. 원인은 다음과 같다.

- 신호 바가 장식처럼 보이고 핵심 업무(표와 예외)보다 먼저 눈에 들어왔다.
- 회색 배경과 경계선이 많아 오래된 관리자 화면 같았다. "카드와 그림자를 없앴다"는 것만으로는 좋은 디자인이 되지 않았다.
- 상태·연결·Plant·기준 시각이 여러 개의 작은 조각(구분선으로 나뉜 칸)으로 흩어져 복잡했다.
- 글꼴(IBM Plex Sans KR), 기본 MUI 요소, 촘촘한 테두리가 결합되어 개성이 약했다.

## 1. 브리프

- **주제:** 제조 현장 MES 웹 클라이언트 (WorkOrder 목록·상세, ProcessUnitStatus 실시간 공정현황, 이후 품질·재고·출하·추적성)
- **사용자:** 생산 현장 운영자(라인 앞 모니터, 장시간 시청)와 생산관리자(여러 작업지시·라인을 비교). 주 환경은 1366×768 이상의 데스크톱 모니터이며 이후 태블릿·핸드헬드 스캔 화면이 추가된다.
- **핵심 업무:** 많은 데이터를 빠르게 훑고 이상 상태를 즉시 알아채는 것.
- **기본 언어:** 한국어. 영어·베트남어 전환 구조는 유지한다.
- **주인공:** ServerDataGrid와 예외 상태. 나머지는 이 둘을 돕는다.

## 2. 새 방향: Quiet Industrial Operations Console

핵심 한 문장: **정상은 조용하게, 예외는 크게.**

장식이 아니라 생산 현장의 명확한 정보 계층과 안정감으로 만든다. 화면이 평소에는 가라앉아 있다가 이상·지연이 생기면 그 위치와 크기와 색으로 곧바로 드러난다. 모든 정보 조각이 같은 크기로 경쟁하지 않는다.

### 2.1 개정 1과 개정 2의 차이

| 영역 | 개정 1 (폐기) | 개정 2 |
|---|---|---|
| 첫인상 | 상단 신호 바가 5칸 + 좌측 내비게이션 + 탭 줄 + 제목 줄 + 리본이 모두 같은 무게로 쌓임 | 위에서 아래로 상단 한 줄(내비·맥락) → 제목 → 예외 → 표. 예외와 표만 크다 |
| 운영 맥락 | 구분선으로 나뉜 4~5개의 칸(Plant, 연결, 기준 시각, 마지막 작업, 사용자) | 상단 한 줄 안의 한 덩어리 문장 구조. 정상일 때는 흐린 글자, 이상일 때만 그 줄이 색·도형·글자로 강조됨 |
| 내비게이션 | 좌측 216px 레일 + 탭 줄 | 상단 모듈 메뉴(작업 영역 전체 폭 확보). 열린 화면 탭은 2개 이상일 때만 얇게 표시 |
| 배경 | 회색 canvas + 흰 panel + 모든 영역 경계선 | 작업 영역은 흰 면 하나. 영역 구분은 간격과 글자 크기로, 선은 표의 행 구분과 머리글 아래 한 줄만 |
| 색 | 회색 계열 + 청록 primary + 상태색 5가지가 동급 | 잉크(거의 검정) + 코발트 액센트 1색. 상태색은 예외(이상·지연)에만 크게, 정상·진행·대기는 잉크·회색으로 조용하게 |
| 상태 표현 | 모든 셀의 상태가 색 글자 + 도형 | 도형·글자·색 + 행 위치(이상 행은 왼쪽 막대 표식). 정상류는 도형을 작고 글자를 보통 굵기로 |
| 요약 | 칸을 나눈 리본, 항목마다 배경 | 한 줄 예외 스트립. 이상·지연은 큰 숫자, 나머지는 작고 흐리게. 선택 시 액센트 밑줄 |
| 전체 상태 | 없음 | 화면 맨 위 3px 경광선(beacon line). 평소엔 거의 보이지 않고 지연이면 호박색, 이상이면 적색 |
| 글꼴 | IBM Plex Sans KR (+ Plex Mono) | SUIT Variable(한글·영문 기하학적이고 단단함) + 식별자 전용 IBM Plex Mono |
| 표 | 회색 머리글 면, 촘촘한 세로·가로 경계 | 가는 행 구분선만, 머리글은 굵은 글자 + 아래 2px 잉크 선, 선택은 액센트 연한 면 + 왼쪽 막대, 가로선은 옅게 |
| 모서리·그림자 | 반경 2px, 드로어만 그림자 | 반경 0~2px 유지. 그림자는 팝오버·드로어만 |
| 오류·빈 상태 | 아이콘 + 제목 + 본문 | 3px 상태색 막대를 앞세운 한 덩어리. 무엇이 일어났는지 + 다음 행동 |

### 2.2 색 토큰 (밝은 테마 기본)

잉크가 중심이고 액센트는 코발트 하나다. 위험·경고 색은 액센트와 색조가 겹치지 않는다.

| 이름 | 값 | 용도 |
|---|---|---|
| surface | `#FFFFFF` | 작업 영역 전체 |
| subtle | `#F4F6F8` | 행 hover, 팝오버 구역 |
| line | `#E4E9EE` | 행 구분선 (옅게) |
| lineStrong | `#7B8895` | 입력 경계, 포커스 밖 강한 경계 (3:1 이상) |
| ink | `#0D1A24` | 본문·숫자·머리글. 순수 검정이 아니다 |
| inkMuted | `#526270` | 보조 글자, 정상류 상태 글자 (4.5:1 이상) |
| accent | `#2447C8` | 현재 위치, 주 명령, 선택, 포커스 링 |
| accentTint | `#E9EEFC` | 선택된 행 |

상태색(전경 ink / 연한 면 tint). 위험·경고만 색이 크다.

| 상태 | 한국어 | ink | tint | 형태 | 비고 |
|---|---|---|---|---|---|
| fault | 이상 | `#9C110B` | `#FCE7E4` | 팔각형 + X | 행 왼쪽 4px 표식, 굵은 글자 |
| delayed | 지연 | `#8A5200` | `#FDF0D2` | 삼각형 + ! | 행 왼쪽 4px 표식, 굵은 글자 |
| ok | 정상 | `#1B7544` | `#E4F3EA` | 원 + 체크 | 보통 굵기, 작은 도형 |
| running | 진행 중 | `#0D1A24` | `#EEF1F4` | 반원 | 중립 잉크. 정상 범위의 진행은 색을 쓰지 않는다 |
| idle | 대기 | `#526270` | `#F1F3F5` | 빈 원 + 대시 | 흐리게 |

경광선(beacon): 평소 `line`, 지연 `#E8A317`, 이상 `#D32F25`. 3px, 화면 맨 위.

다크 테마는 같은 구조를 반전한다: surface `#0F1A23`, subtle `#16232E`, line `#25343F`, lineStrong `#6F818F`, ink `#E8EEF3`, inkMuted `#A3B1BC`, accent `#8FA9FF`, accentTint `#1B2850`. 상태 ink는 이상 `#FF8E84`, 지연 `#F2B864`, 정상 `#7FD6A4`, 진행 `#E8EEF3`, 대기 `#A3B1BC`. 경광선은 지연 `#E8A317`, 이상 `#FF5A4F`.

### 2.3 타이포그래피

- **UI·본문:** SUIT Variable. 한글과 영문이 같은 기하학적 구조로 단단하고, 굵기 축이 있어 한 가족으로 계층을 만든다. 자체 호스팅(`@sun-typeface/suit`)이라 공장 내부망에서도 CDN이 필요 없다.
- **식별자 전용:** IBM Plex Mono. LOT, QR, 작업지시번호처럼 문자 단위로 비교하는 값에만 쓴다.
- **숫자:** 표·스트립·맥락 줄 전체 `font-variant-numeric: tabular-nums`. 수량·시간 열은 우측 정렬.
- **계층은 크기와 굵기로 만든다.** 페이지 제목 1.25rem/700, 예외 숫자 1.625rem/700, 본문 0.875rem, 표 0.8125rem, 맥락·보조 0.75rem. 머리글은 0.75rem/600 보조 색 + 아래 2px 잉크 선. 자간은 제목에만 -0.01em.
- 대문자 라벨, 점으로 이은 메타 문자열, 값 위의 장식 소제목은 쓰지 않는다.

- **상단 한 줄:** 왼쪽에 MES 표지와 모듈 메뉴, 오른쪽에 운영 맥락(Plant, 연결, 기준 시각, 사용자, 표시 설정). 평소에는 흐린 글자이고 이상이 생기면 그 줄 오른쪽에 `이상 N`·`지연 N`이 도형과 함께 색으로 나타난다. 연결이 끊기면 연결 항목이 도형·글자·색으로 강조되고, 같은 줄의 기준 시각에 경과 시간이 붙는다.
- **모듈 메뉴:** 모듈 이름을 누르면 해당 화면 목록이 열린다. 현재 모듈은 액센트 밑줄과 굵은 글자로 표시한다.
- **열린 화면:** 탭이 2개 이상일 때만 제목 위에 한 줄로 나타난다.
- **예외 스트립:** 이상·지연이 항상 맨 앞. 숫자가 크고 나머지는 작고 흐리다. 0건은 사라지지 않고 자리를 지키되 더 흐리다. 항목을 누르면 표 필터가 걸린다.
- **상세:** 우측 드로어(420~560px)가 표 위에 겹친다. 그림자는 드로어에만 허용한다. 선택 id는 URL에 반영(후속 티켓).
- **작업·스캔형 화면(후속):** 큰 입력 영역 + 하단 고정 작업 바, 대상 44px 이상.
- **정렬:** 모든 글자 좌측 정렬, 숫자·시간 우측 정렬. 상태 열은 첫 열에 둔다.
- **반응형:** 1366px 이상이 기준. 1100px 미만에서 사용자 이름·기준 시각의 경과 시간을 줄이고, 900px 미만에서는 모듈 메뉴를 "메뉴" 버튼 하나로 합친다. 가로 스크롤은 표 내부에서만 허용한다.

### 2.5 정보 밀도와 상태 표현

- **밀도:** compact(행 32px, 기본), standard(40px), comfortable(52px). 사용자 설정은 localStorage.
- **정상은 조용하게:** 정상·진행·대기는 잉크 또는 보조 색, 보통 굵기, 작은 도형. 눈이 가야 하는 곳은 이상·지연뿐이다.
- **예외는 세 겹 + 위치:** 이상·지연은 굵은 글자, 도형, 색, 그리고 행 왼쪽 4px 표식과 예외 스트립의 맨 앞이라는 위치로 표현한다. 색만으로 의미를 전달하지 않는다.
- **상태 표시 컴포넌트:** `StatusBadge`가 유일한 진입점이다. pill(알약형 배경)은 쓰지 않는다. 연한 면(tint)은 예외 스트립의 예외 항목과 오류·빈 상태에만 쓴다.
- **선택:** 행 선택은 `accentTint` 면 + 왼쪽 액센트 막대. 이상 행은 왼쪽 표식을 유지하고 면만 바뀐다.
- **데이터 신선도:** 상단 한 줄에 연결 상태와 기준 시각을 항상 둔다. 오래된 데이터는 경과 시간이 기준을 넘으면 `지연` 형태로 바뀐다.
- **오류·빈 상태:** 3px 상태색 막대 + 도형 + 제목 + 한 문장 본문 + 다음 행동. 사과하지 않고 원인과 조치를 말한다.
- **버튼 문구**는 실제 동작과 같은 동사를 쓴다.

### 2.6 접근성·움직임

- 본문 4.5:1, UI 경계 3:1 이상. 모든 상태색 쌍은 토큰 테스트로 검증한다(`tokens.test.ts`).
- 색각 이상: 이상·지연은 도형·글자·위치로도 구분된다. 정상(녹색)은 쓰임이 조용하므로 적색과의 혼동 위험이 낮다. 이상과 정상은 밝기도 다르게 잡고 테스트로 고정한다.
- 키보드: 모든 기능을 키보드로 쓸 수 있다. 포커스 링은 액센트 2px + 2px 간격(경계와 겹치지 않음). 건너뛰기 링크. 모듈 메뉴는 메뉴 버튼 패턴(방향키, Esc).
- `prefers-reduced-motion`에서는 모든 전환을 제거한다.
- live region은 상태 전환만 알린다. 경광선의 전체 상태 문구(`role="status"`, 화면에는 숨김)와 연결 상태(`status`, 끊김은 `alert`)만 live region이며, 기준 시각·경과 시간 같은 동적 시계와 이상·지연 건수는 live region에 넣지 않는다. 시계가 흘러도 보조기술 알림이 반복되지 않는다는 점은 `liveRegions.test.tsx`가 검증한다.
- 클릭 대상: 조회 화면 28px 이상, 작업·스캔 화면 44px 이상.
- 움직임은 상태 변화·사용자 행동에 대한 응답만 쓴다. 드로어 150ms, 재연결 표시. 진입 애니메이션, hover 확대, 그라데이션은 쓰지 않는다.

### 2.7 시각적 차별점 (기억에 남길 한 곳)

**경광선과 "정상은 조용하게" 규칙.** 화면 맨 위 3px 선이 전체 상태를 색으로 알리고(평소에는 거의 안 보임), 그 상태는 상단 한 줄과 예외 스트립의 글자·도형으로도 읽힌다. 정상 화면은 거의 흑백 잉크로 가라앉아 있어서 이상·지연이 생기면 곧바로 눈에 들어온다. 나머지는 모두 조용하게 둔다.

## 3. 2단계: 브리프 대조 자체 검토 (재작성)

"같은 요청을 받으면 처음 떠오르는 결과"와 개정 2 계획을 비교한다.

| 처음 떠오른 안 | 문제 | 수정 |
|---|---|---|
| 좌측 어두운 남색 사이드바 + 흰 작업 영역 | 관리자 템플릿에서 가장 흔한 구성. 개정 1의 "오래된 관리자 화면" 인상을 되살린다 | 사이드바를 없애고 상단 한 줄 메뉴로 바꿔 표가 폭 전체를 쓰게 한다 |
| 청록·파랑 계열 primary와 파랑 "진행 중" 상태 | 액센트와 상태색이 겹쳐 주 명령과 진행 상태가 구분되지 않는다 | 액센트는 코발트 하나, 진행 중은 색 없는 중립 잉크 도형으로 |
| 요약 영역을 KPI 타일 4개 + 큰 숫자 | SaaS 대시보드 기본형, 숫자만 있고 행으로 이어지지 않는다 | 한 줄 예외 스트립. 이상·지연만 큰 숫자이고 누르면 표 필터가 걸린다 |
| 모든 상태를 색 pill로 표시 | pill 남발, 모든 행이 색으로 경쟁해 예외가 묻힌다 | 정상류는 조용한 글자, 예외만 굵은 색 + 행 표식. pill 없음 |
| 영역마다 1px 테두리와 회색 면으로 구분 | 개정 1의 문제 그대로 | 간격과 글자 크기로 위계. 선은 행 구분(옅음)과 머리글 아래 2px뿐 |
| 상태 바를 항상 같은 무게로 5칸 표시 | 정상일 때도 눈길을 빼앗음 | 정상일 때 흐린 한 줄, 이상일 때만 강조. 경광선은 평소 거의 안 보임 |
| IBM Plex Sans KR / Pretendard / Noto Sans KR | 각각 개정 1의 결과 / 한글 UI의 가장 흔한 기본값 / 기본값 | SUIT Variable. 한글·영문이 같은 기하학적 구조이고 굵기 축으로 계층을 만든다 |
| 어두운 near-black + 형광 포인트의 관제 화면 | 흔한 다크 대시보드이고 밝은 현장에서 눈부심 대비가 크다 | 밝은 테마 기본. 다크는 같은 토큰의 반전 선택지 |
| 라벨마다 영문 대문자 소제목, "A · B · C" 점 연결 메타 | 템플릿 흔적 | 쓰지 않는다. 맥락 줄은 항목 이름 + 값을 공백으로 구분 |
| 버튼 "→", 진입 애니메이션, 그라데이션 | 장식 | 모두 제거 |

그래도 남는 위험과 대응:

- **밝은 흰 면 + 잉크 + 단일 액센트**는 최근 도구형 SaaS의 흔한 조합과 닮을 수 있다. 차별점은 색 조합이 아니라 (1) 경광선과 "정상은 조용하게" 규칙, (2) 크기로 위계를 만든 예외 스트립, (3) 도형 문법과 행 표식으로 상태를 읽는 표다. 이 셋이 장식이 아니라 업무 정보라는 점을 기준으로 유지한다.
- **상단 한 줄이 붐빌 위험:** 모듈 6개 + 맥락 5항목이 1366px에 들어가는지 캡처로 확인하고, 좁은 폭에서는 항목을 줄이는 규칙을 둔다.
- **모듈 메뉴가 화면 이동 클릭을 늘릴 위험:** 운영자는 주로 열린 화면 탭에서 이동하고, 모듈 메뉴는 전환용이다. 화면이 늘어 불편하면 최근 화면 목록을 메뉴 맨 위에 둔다(후속).

"장식 하나를 빼고 나간다" 점검: 상단 오른쪽 `이상 N · 지연 N` 요약이 예외 스트립과 중복된다는 점을 검토했다. 다른 화면으로 이동해도 전체 이상이 보이게 하려는 목적이 있어 유지하되, 이상·지연이 모두 0이면 나타나지 않게 한다.

## 4. 최종 설계 결정 (구현 기준)

1. 토큰은 `src/app/theme/tokens.ts` 한 곳에 둔다. 컴포넌트는 `theme.mes`의 의미 토큰만 참조한다.
2. 기본 테마는 라이트. 다크는 같은 구조의 두 번째 팔레트.
3. `StatusBadge`가 상태 표현의 유일한 진입점이다. 상태 enum은 표시 상태(`ok`, `running`, `delayed`, `fault`, `idle`)이며 WorkOrder 업무 상태값과 직접 연결하지 않는다. 업무 상태 → 표시 상태 매핑은 각 feature가 소유한다.
4. 상단 한 줄(`TopBar`)이 내비게이션과 운영 맥락을 함께 가진다. 값은 FE-04(Plant, 사용자), FE-10(연결, 기준 시각), 화면(이상·지연 합계)이 채운다.
5. 전체 상태는 `OperationalStatus` context로 화면이 보고하고, 경광선과 상단 요약이 읽는다.
6. 표는 `ServerDataGrid`(FE-05)를 쓰며 compact 기본, 200행 상한, 가상화 유지. 표 스타일(머리글, 행 구분, 선택, 예외 행 표식)은 theme에서 정의해 같은 모양을 쓴다.
7. 한국어 문구는 i18n 리소스에만 둔다.
8. 새 화면은 §2.4 레이아웃을 따르며 카드, 그림자, 그라데이션, pill을 추가하지 않는다.

## 5. 구현 후 비평 기록

개정 2를 FE-03 AppShell과 임시 화면(`/dev/signals`, `/dev/density`)에 적용하고, 1366×768과 800×700, 라이트·다크, 정상·지연·이상·연결 끊김 시나리오를 캡처해 비평했다.

개정 1과 비교해 달라진 점:

- 첫 시선이 상단 장식이 아니라 제목 → 예외 스트립의 큰 숫자 → 표로 흐른다. 이상 3·지연 12가 가장 큰 글자이고 나머지는 작고 조용하다.
- 정상 화면은 거의 잉크 흑백이라 이상·지연 행의 왼쪽 표식과 굵은 색 글자가 곧바로 눈에 들어온다. 표는 회색 면과 세로선 없이 가는 가로선과 머리글 아래 2px 선만 쓴다.
- 상단 한 줄이 내비게이션과 운영 맥락을 함께 갖는다. 연결 끊김 시나리오에서 경광선 적색, `끊김` 도형, `마지막 기준 10:41:55 (45초 전)` 강조가 같은 줄에서 한 번에 읽힌다.
- 좌측 레일이 없어져 표가 폭을 전부 쓰고, 800px에서도 구조가 바뀌지 않는다(모듈 메뉴가 "메뉴" 하나로 합쳐짐).

비평 후 고친 점:

| 발견 | 수정 |
|---|---|
| 밝은 테마의 호박색 경광선(`#E8A317`)이 흰 면에서 대비 2.2:1로 약함 | `#BF7A00`으로 어둡게 하고 3:1 이상을 토큰 테스트로 고정 |
| 어두운 테마에서 메뉴·팝오버가 배경과 섞여 경계가 보이지 않음 | 팝오버 면을 한 단계 올리고 가는 선을 추가 |
| 한글 안내 문장이 단어 중간에서 줄바꿈됨("각 모/니터링") | 본문에 `word-break: keep-all` 적용 |
| 표 셀의 상태 도형·글자가 행 중앙보다 약간 위에 붙음 | 상태 표시에 `vertical-align: middle` 적용 |
| 액센트(코발트)와 상태색 구분이 말로만 보장됨 | 액센트 색조가 이상·지연·정상과 40도 이상 다름을 토큰 테스트로 고정 |

의도적으로 남긴 점:

- 상단 오른쪽 `이상 N`·`지연 N`은 예외 스트립과 중복이지만, 다른 화면에서도 전체 이상이 보이게 하려는 목적이라 유지했다. 0건이면 나타나지 않는다.
- 모듈 메뉴는 화면 이동에 클릭 한 번이 더 든다. 운영자는 열린 화면 탭으로 이동하므로 허용한다. 화면이 늘어나 불편하면 메뉴 맨 위에 최근 화면을 둔다(후속).
- 정상(녹색) 도형은 작고 보통 굵기다. 이상과 같은 크기·굵기로 경쟁하지 않게 하기 위한 의도다.

정적 자산 예산: SUIT Variable 글꼴 파일(약 610KB)은 JS 예산과 별개의 정적 자산이다. FE-11 성능 측정에서 자산 예산으로 따로 확인한다(아직 측정 전이며 기준 수치는 정하지 않았다).

측정 기록(FE-03 개정 2 시점): 초기 Shell JS 번들은 예산 300KB(gzip) 이내이며 값은 `npm run bundle:size`로 확인한다. SUIT Variable 글꼴은 약 610KB의 woff2 한 파일이고 JS 예산에는 포함되지 않는다(font-display: swap, 한 번 받으면 캐시).

다음 비평 지점: FE-05 `ServerDataGrid`에서 compact 밀도와 가상화를 실제 데이터 200행으로 확인하고, 선택·키보드 이동·예외 행 표식이 같은 모양으로 쓰이는지 본다. FE-08에서 예외 스트립을 실제 건수와 연결해 다시 기록한다.
